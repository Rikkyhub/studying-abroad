### 計算ルール

| 項目 | 計算方法 |
|---|---|
| 総費用予測 | 各行の見積（低予算・標準・余裕）を円に換算して合計する。支払済み額が見積より大きい行は支払済み額を使う。実績（`actual_jpy`）が入った行は実績だけを使う |
| 二重計上の防止 | 支払済み額は、その行の見積の**内側**にある金額として扱う。総額に足し込まない |
| 支払済み（証憑確認済み） | 区分が「確定」または「実績」で、`evidence` に記入がある行の `paid_jpy` の合計 |
| 支払済み（暫定） | 証憑のない `paid_jpy`。行の区分は「未確認」になる |
| 今後必要な支払額 | 総費用予測（標準）− 支払済み |
| 利用可能資金 | `funds.csv` の「資金」行の合計。支払済み分を差し引いた後の、これから使える資金 |
| 資金の不足・余剰 | 利用可能資金 − 今後必要な支払額 |
| 実費総額 | 区分が「実績」の行の `actual_jpy` の合計 |
| 金額が未入力の行 | **0円として扱わない**。総額には含めず、件数と一覧を表示する。その間の総額は「入力済み分の合計」として読む |
| 為替 | 見積は `fx.csv` のレートで換算する。実績には、実際に引き落とされた円の額を `actual_jpy` に、適用されたレートを `actual_fx` に記録する |

## 7. 更新のしかた

1. **見積が出たら**、該当行の次の列を更新し、区分を「見積」にする。
   - `low_local`・`std_local`・`high_local`
   - `currency`・`source`・`collected_on`・`recheck_by`
2. **申込・支払が済んだら**、次を記入する。
   - `paid_jpy`・`paid_date`
   - `evidence`：**非公開の保管場所でのラベルだけ**を書く（例：`private:2026-10_PINES_invoice`）。領収書の画像や予約番号はコミットしない。
   - 証憑で金額を確認できたら、区分を「確定」にする。
3. **利用が終わったら**、`actual_jpy`・`actual_local`・`actual_fx` を記入し、区分を「実績」にする。
   - 一度記入した実績は書き換えない。訂正するときは `note` に「YYYY-MM-DD 訂正：旧→新（理由）」と残す。
4. 費用を追加するときは、新しい ID の行を足す。接頭辞は次のとおり。
   - PH-：フィリピン
   - AF-：アフリカ周遊
   - SC-：2校目
   - AU-：8月
   - CM-：共通・日本
5. `python3 scripts/build.py` を実行して、生成物も一緒にコミットする。CI は `--check` で、生成物が CSV と一致しているかを検証する。
