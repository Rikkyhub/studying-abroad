### 初版と更新版の差分の検証方法（A22／2026-10-29・一般公開モデル）

同じ `data/expenses.csv` の行IDをキーに、**初版・更新版の各スナップショット**を比較する。変更前後のファイル版（commit SHA）・確認日・掲載適用年・出典URLをセットで残し、更新版の数字だけを見て「節約した」と表現しない。

| 差分の種類 | 判定・記録方法 | 実際の支出と区別する点 |
|---|---|---|
| 計算・入力の訂正 | 同じ条件の計算式や転記を直した差。旧値・新値・訂正理由を記録 | 節約額ではなく**見積誤差の修正** |
| 対象範囲・数量の変更 | 行ID・人数・泊数・食数・含有サービス・重複項目の変更を分離 | 料金が下がったとは言えない |
| 現地価格の改定 | **同じ商品・同じ適用条件・同じ通貨**の旧価格と新価格を比較 | 2026年掲載額を2027年の実売と扱わない |
| 為替換算の変更 | 同じ外貨額を同じ換算ルールで別の参考レートに換算 | 市場参考レートとカード請求額は異なる |
| 新規・削除・未入力 | 新規行・対象外化・空欄を別集計する | 空欄を0円や節約額として差し引かない |

**同一条件の分解例（説明用の数式）**：旧数量 `q0`、旧現地単価 `p0`、旧参考円レート `r0`、更新値 `q1,p1,r1` の場合、総差額 `q1*p1*r1 - q0*p0*r0` を、数量差 `(q1-q0)*p0*r0`、単価差 `q1*(p1-p0)*r0`、為替差 `q1*p1*(r1-r0)` に分ける。**対象商品・含有条件が異なる場合や旧値が空欄の場合はこの分解を行わない。** 複数通貨は通貨ごとに分ける。

### 見積を改訂するときの照合手順（2026-10-29）

この節は**公開用の見積モデルの更新方法**であり、個人の支払実績ではない。現在の上記AUTO集計はPH-08・AF-04・AF-09・AF-11・AF-12・CM-09等のCSV訂正前の旧値です。正式生成器で再計算・検証するまで数値を意思決定に使用しない。

1. `data/expenses.csv` の各IDについて、出典URL・確認日・適用期間・通貨・数量・税/手数料の包含条件を記録する。未確認の金額は空欄を維持し、0円と区別する。
2. **価格改訂差**＝同じ通貨・同じ数量/条件での「新しい掲載価格 − 旧掲載価格」。条件・プランが変わる場合は価格改訂と混ぜず別の差分として記録する。2026年の掲載料金を2027年確定値にしない。
3. **為替差**＝同じ外貨建て金額×（新しい参考円換算レート − 旧参考レート）。価格差と為替差を分け、基準日・通貨を必ず併記する。外貨建て金額も変わる場合は価格差を旧レートで評価し、為替差を新金額で評価するなど**計算順を明示**して二重計上を防ぐ。
4. **対象範囲差**＝新たに含める/除外する費目・宿泊日数・食事・ツアー・返金可能な預り金などの差。支払前の見積、前払、返金、実費は混ぜない。条件の異なる3プランの合計を「同一プランの時系列推移」とみなさない。
5. 変更前後のCSV、更新した根拠、見積モデルの版/基準日をGit履歴で比較し、正式`scripts/build_all.py`・既存validator・公開匿名化検査の後に生成Markdown/HTMLと合計を照合する。生成できない間は旧AUTO集計を**要再生成**と明示する。

### 5-1. 住居維持と退去の比較（T-H02）

2026-10-24に一般モデルを整備。**実際の契約・支払額や個別の退去日を公開しない**。次の金額はすべてJPYで、2027年の契約費用を確定するものではない。

| 選択肢 | 比較式（同じ不在月数 N を使う） | 入力が必要な費用 |
|---|---|---|
| 住居を維持 | N×月額家賃＋N×残る基本料金＋契約更新費等 | 家賃・共益費、通信/電気等の最低料金、更新料 |
| 退去して再入居 | 退去費＋原状回復の実負担＋保管費＋帰国後の新契約費＋再引越費 | 契約上の解約予告・違約金、原状回復、仲介/敷金等、荷物量、配送 |
| 実家等へ保管 | 保管サービス料金0円は**無償で預けられる場合だけの仮定**。搬送費は別 | 受入可否・箱数・往復運送費 |

- **比較判定**：同じ期間・同じ荷物量で「維持総額 − 退去総額」を計算し、正なら退去案の方が低コスト。退去後の新規賃貸契約は費用・審査・空室が未確定であり、安いことを保証しない。
- **宅配保管の2026年公式料金に基づく参考例（レギュラー3箱・月額満額・一括取出し・税込）**：6か月ならminikura HAKO **9,060円**／サマリーポケット エコノミー **9,240円**。8か月ならそれぞれ **10,980円**／**11,220円**。式は「月額×3箱×月数＋1,100円×3箱」。初月日割り、早期取出し、配送先による追加費用、料金改定は除外。
- **CM-07の2026年公式料金による匿名モデル（2026-10-29照合）**：8か月のサマリーポケット・エコノミーレギュラーを1箱／2箱／3箱利用し、各箱を1回取り出す場合は、それぞれ **3,740円／7,480円／11,220円**（330円×8か月＋1,100円を箱数倍）。[事業者公式料金](https://pocket.sumally.com/pricing)。2027年料金・箱数・初月日割り・早期取出し・キャンペーン・追加送料は未確定。契約・実費ではない。\n- **費用の二重計上禁止**：`data/expenses.csv` の CM-07 は有料宅配保管を利用する場合のモデル、CM-08 は住居維持または退去・再契約の**選択肢**。CM-08に保管費を含めたときはCM-07に再加算しない。無償保管を選ぶ場合もCM-07のモデル額を実費として加算しない（搬送費は別）。CM-08は契約条件が決まるまで金額空欄（0円ではない）。
- **一次資料（2026-10-24確認）**：[minikura料金](https://help.minikura.com/hc/ja/articles/221046527-%E6%96%99%E9%87%91%E3%81%AB%E3%81%A4%E3%81%84%E3%81%A6)／[サマリーポケット料金](https://pocket.sumally.com/pricing)／[国交省・原状回復ガイドライン](https://www.mlit.go.jp/jutakukentiku/house/jutakukentiku_house_tk3_000020.html)。国交省のガイドラインは一般的な負担基準で、個別の賃貸契約や原状回復請求額を確定するものではない。

## 7. 更新のしかた

1. **公開料金の見積が見つかったら**、該当行の `low_local`・`std_local`・`high_local`・`currency`・`source`・`collected_on`・`recheck_by` を更新し、区分を「見積」にする。
2. 出典がない推定は区分を「未確認」にする。金額が分からなければ空欄のままにする（0を入れない）。
3. 個人の請求・支払い・領収書・資産は**公開CSVに書かない**。列も追加しない（`check_public_data.py` が CI で検出する）。
4. 費用を追加するときは、新しい ID の行を足す。接頭辞は PH-（フィリピン）／AF-（アフリカ周遊）／SC-（2校目）／AU-（8月）／CM-（共通・日本）。
5. `py scripts/build_all.py` を実行して、生成物も一緒にコミットする。CI は `--check` で、生成物が CSV と一致しているかを検証する。
