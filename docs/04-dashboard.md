# トップページと地域別ページの見方・更新方法

読者が見るのは `index.html`（トップ）と `areas/` の地域別ページ（バギオ・アフリカ周遊・ケープタウン・共通）です。どれも静的HTMLで、外部ライブラリ・サーバー不要、`file://` で直接開いて読めます。CSV は読者向けの表示対象ではありません（生成スクリプトの内部入力です）。

```sh
py scripts/build_all.py          # 生成物をすべて更新（入口はこれ1つ）
py scripts/build_all.py --check  # 生成物が元データと一致するか検証（CIで実行）
```

Linux/macOS では `py` の代わりに `python3` を使います。

## 手で書くもの・生成されるもの
| 種類 | 例 | 扱い |
|---|---|---|
| 手で編集する Markdown | `areas/*.md` の導入文・見出し、`docs/*.md`、`research/*.md`、`blog/*.md` | 正本。ここを直す |
| 自動生成のブロック | Markdown 内の `<!-- AUTO:名前 -->` 〜 `<!-- /AUTO:名前 -->` の間 | `scripts/build.py` が作り直す。手で直しても上書きされる |
| 生成されるHTML | `index.html`、`areas/*.html`、`research/*.html` など全 `*.html` | 手で編集しない。Markdown から生成 |
| Word | `exports/`（コミットしない） | `py scripts/export.py docx`（地域別ページも対象） |
| 内部入力（CSV） | `data/*.csv` | 費用・タスク・日程・資料・場所・為替の元データ。生成スクリプトだけが読む |

## 生成の流れ（2段階・順序固定）
| 順 | スクリプト | 読むもの | 書くもの |
|---|---|---|---|
| 1 | `scripts/build.py`（地域別の表は `scripts/areas.py`） | `data/*.csv` と `research/africa-route-comparison.md` の表 | `README.md`・`docs/01〜03`・`blog/article-ideas.md`・`areas/*.md` の AUTO ブロック |
| 2 | `scripts/build_html.py` | 上記の Markdown と `data/*.csv` | `areas/`・`research/`・`docs/`・`blog/` の `*.html`、`docs/09-issue-map.*`、`index.html` |

順序が逆だと HTML が AUTO ブロック更新前の内容になります。何度実行しても同じ結果になります（テストで確認）。

## 地域別ページの構成
各ページは次の順です：(1) 概要と時期（モデル） (2) いまの確認事項（優先度つき・相対期限・期限の種類） (3) 費用の見積（低予算/標準/余裕、小計つき） (4) 資料（参考リンクを表内に） (5) 場所と地図（Google マップ） (6) 通貨と円換算。アフリカ周遊にはルート案の表と地図の節があります（`maps/world-map.html`・`maps/africa-map.html` が存在するときだけリンクします）。

- 費用は `expenses.csv` の `phase` 列で地域に分けます（フィリピン→バギオ、アフリカ周遊→アフリカ、2校目・8月→ケープタウン、共通・日本→共通）。
- 確認事項・旅程・資料は、`tasks.csv`・`timeline.csv`・`pages.csv` の `region` 列（`baguio`/`africa`/`capetown`/`common`、複数は `;` 区切り）で振り分けます。新しい行を足すときは `region` を必ず付けます（`validate_data.py` が確認）。
- 金額が入っていない項目は「未計上」と表示し、0円にも小計にも含めません。通貨が違う行は `fx.csv` の参考レートで円に換算してから小計を出します（換算前の合算はしません）。

## トップページ
浮遊カードで構成します。節の順は 予算の全体像（目標総予算・上限予算・5月アフリカ周遊の目安・見積合計）／旅程（期間ごとに1枚、地域別ページへのリンク）／地域別（地域ごとに1枚）／いま何をするか／通貨と円換算（通貨ごとに1枚＋電卓）／資料一覧（カード内の表）／フッターです。長い表は地域別ページにあります。支払い・実費・利用可能資金・残額は表示しません。表示する金額はすべてモデルの目標・見積で、支払済み・確定を意味しません。金額未入力の項目は「未計上」と書き、0円にも合計にも含めません。

### デザイン規則（トップページ＝浮遊カード、詳細ページ＝表）
- カードは白（ダークでは画面より少し明るい面）、画面の背景はごく薄いグレー。枠線は無しか極薄、影は `0 10px 30px rgba(0,0,0,.05)` のように薄く広く。
- カード間の余白は 28px、カード内の余白は約22px。列は `repeat(auto-fill,minmax(240px,1fr))`、幅は最大1100px。400px幅では1列。
- ホバーで `translateY(-10px)` 浮き上がり、影が濃く下へ広がる（0.3秒、`transition`）。`@media (hover:hover)` の端末だけ。`prefers-reduced-motion` では動かさない。
- リンクのカードは全体を1つの `<a>` にする（入れ子のリンクは作らない）。キーボードのフォーカスは外枠で示す。
- 左側の線（`border-left` の帯）は使わない。注意書きは薄い色の背景だけ。絵文字・グラデーション・アイコンの丸囲みも使わない。
- 地域別ページなど詳細ページはカードにせず、共通テンプレートの表（読みやすさ優先）を使う。

## 見やすさの方針
- 本文16px、行間1.8、文章の幅は約72文字まで。表は列幅を割り当て、折り返して1100px幅で横スクロールが出ない構成にする。狭い画面（約760px以下）では表だけが枠内で横にスクロールし、ページ全体は動かない。
- 見出し行は固定、数値は右寄せ（桁を揃える）。上部にページ間の移動バー、各ページ冒頭にページ内目次。ライト／ダークの配色トークン、絵文字・グラデーションは使わない（カードはトップページだけ）。
- 全生成ページで同じテンプレート（`scripts/build_html.py` の `BASE_CSS` / `PAGE`）を使う。

## 内部入力（CSV）の列
- `data/expenses.csv`：費用の見積（区分は `見積`＝出典あり／`未確認`）。支払い・実績の列は置かない。期間は月単位のモデル値。
- `data/funds.csv`：予算目標のみ（type=予算）。個人の資金・残高は置かない。
- `data/fx.csv`：`currency,name_ja,unit,region,jpy_per_unit,rate_date,rate_kind,source`。レートが空欄の通貨は「未確認」と表示し、0円扱いにしない。
- `data/pages.csv`：資料の表。`refs` 列に根拠にした一次情報のURLを `;` 区切りで最大3件。`region` 列で地域に振り分け。`issue` 列は読者向けの表には出さず、保守者向けの [Issue対応表](09-issue-map.md) にだけ出る。`research/`・`docs/`・`blog/`・`areas/` の新しいページはここに行を足す。
- `data/timeline.csv`：旅程（月単位。日単位の日付は `validate_data.py` が検出）。`region` 列つき。
- `data/tasks.csv`：準備タスク。`region` 列つき。期限は暦日ではなく相対表記。
- `data/places.csv`：場所と地図。公共の施設・名所・ショップ・空港だけを `maps_query` で書く（自宅・宿泊先・予約情報は書かない）。

## 為替レートの更新
1. 公開されている参考レート（現在は MUFG の対顧客外国為替相場の仲値TTM、https://www.murc-kawasesouba.jp/fx/index.php ）を確認する。
2. `data/fx.csv` の `jpy_per_unit`・`rate_date`・`rate_kind`・`source` を更新する。取得できない通貨は `jpy_per_unit` を空にする（推測値は入れない）。
3. `py scripts/build_all.py` で再生成する。
- これは参考レートで、現金両替・ATM・カードのレートとは一致しない。

## 今後の検討（費用・タスクを Markdown の表に移すか）
今回は費用（`expenses.csv`）とタスク（`tasks.csv`）の数値データを CSV から動かしていません。読者が直接見るのは Markdown/HTML だけなので、次のような移行も考えられます。判断はオーナーにお任せします。
- 案A（現状維持）：CSV は内部入力のまま。編集は表計算ソフトでもでき、検証（列・数値・日付）が機械的にできる。
- 案B：地域別ページの費用・確認事項の表を Markdown の表として手書きし、`build.py` がその表を解析して集計（小計・円換算・未計上の判定）する。メリットは「見えているものがそのまま正本」になること。課題は、列の取り違え・金額の書式ゆれ（カンマ・全角）・通貨と円換算・未計上と0の区別を、パーサで厳しく検証する必要があること。
- 案Bに進む場合の手順：(1) 表の列と書式を決める（ID・項目・区分・通貨・低/標準/余裕・出典）。(2) パーサと検証を先に作り、現在の CSV と結果が一致することをテストで確認する。(3) 1地域ずつ移し、最後に CSV を削除する。

## 公開に関する注意
リポジトリは公開状態。内部入力にも個人の支払い・資産・証憑、個人が特定される情報、予約番号、宿泊先住所を書かない（[公開データ方針](05-public-data-policy.md)）。個人の実績は非公開のNotionで管理する。`check_public_data.py` は禁止列・個人資金行を、`validate_data.py` は番号・メール・電話番号らしき値を検出する。自動検査は補助で、目視確認も行う。
